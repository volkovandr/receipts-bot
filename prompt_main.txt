=== CRITICAL RECOGNITION STRATEGIES ===

1. LAYOUT UNDERSTANDING (fixes alignment issues):
   - Receipts follow a structured layout: [Item Name] [spaces/dots] [Price]
   - Prices are right-aligned
   - In many times to the right of the price there is a VAT indicator: Digits 1 or 2 or letters A or B. Ignore them.
   - If you see a number on the right edge, it's likely a price
   - Work BACKWARDS: find all prices first, then match them to item names on the same line
   - Multi-column receipts: items are in the left column, prices in the right column
   - Some receipts use table format with columns: Item | Quantity | Unit Price | Total
   - CRITICAL: Trust the right-aligned price over calculation from weight/quantity info
   
2. MULTI-LINE ITEM DETECTION:
   - If a line has NO PRICE, it's likely a continuation of the previous item OR a quantity line
   - Common patterns:
     * Line 1: "PRODUCT NAME WITH"
     * Line 2: "LONG DESCRIPTION" → these are ONE item
   - Indented lines without prices can be:
     * Item name continuation (descriptive text)
     * Quantity/weight information (numbers with "x", "kg", "€/kg", "Stk")
   - Look for these continuation indicators:
     * No price on the line
     * Indentation or spacing differences
     * Lowercase start (continuing a sentence)
   - When merging multi-line items, handle quantity lines separately (see Step 3)
   
   WEIGHT/QUANTITY LINE IDENTIFICATION:
   - Quantity lines contain: "N x price €" or "N Stk x price" or "N.NNN kg x price €/kg"
   - These lines have NO right-aligned price
   - They are typically indented
   - They can appear ABOVE or BELOW the item they describe
   - In table format receipts, quantity appears in a column on the SAME LINE as the item
   - DO NOT immediately assign them - verification required (see Step 3)
   
3. DISCOUNT HANDLING:
   Two types of discounts:
   
   a) INLINE DISCOUNTS (DO NOT create separate items):
      - Appear as text below an item WITHOUT a right-aligned price
      - Example:
        PRODUCT NAME          5.99
        Rabatt 10%
      - Attach these to the previous item in the "notes" field
   
   b) SEPARATE DISCOUNT ITEMS (DO create separate items):
      - Have their own RIGHT-ALIGNED price (usually negative)
      - Example:
        PRODUCT NAME          5.99
        RABATT AKTION        -1.00
      - These are separate line items that you paid (or saved)
      - Include them as separate items in the extraction
   
   Rule: If there's a right-aligned price/amount → it's a separate item

4. DEPOSIT HANDLING (IMPORTANT - ALWAYS INCLUDE):
   - Deposits (PFAND) are amounts you actually pay
   - Common patterns:
     * "PFAND 0.25 €" or "PFAND 1.50 EURO"
     * "LEERGUT" (bottle return - can be negative if returning)
     * "Pfandgebinde" or similar terms
     * Individual bottle deposits listed with items
   - include deposits as separate items
   - If deposit return (negative amount), still include it - it affects total paid

5. NON-ITEM DETECTION (don't include as items):
   - Subtotals: "SUMME", "ZWISCHENSUMME", "Subtotal", "ZU ZAHLEN", "ENDSUMME" (when explicitly labeled as subtotal)
   - Tax lines: "MwSt", "VAT", "Steuer %" (only when showing tax breakdown, not item tax codes like "B" or "A")
   - Payment lines: "ZAHLUNG", "BEZAHLT", "Geg. EC-Cash", "Bar", "Kartenzahlung", "KARTENZAHLUNG EUR", "ZU ZAHLEN". 
     Sometimes the payment line is listed right after the list of items with a negative amount. This is not an item!
   - Final totals: "GESAMT", "TOTAL" (when clearly the final line)
   - Anything that comes after the total amount "SUMME EUR"
   - Receipt footer: "Danke", "Vielen Dank", promotional text, "Maestro", payment method names
   
   KEY DISTINCTION: 
   - If it has a right-aligned price and is NOT explicitly a subtotal/tax breakdown/payment line → it's an item
   - When in doubt: if you paid for it individually, it's an item

6. ABBREVIATION DECODING (GERMAN):
   German grocery abbreviations - expand to German terms in item notes when helpful:
   - "KG-WARE" = nach Gewicht verkauft (sold by weight)
   - "Stk" = Stück (pieces)
   - Store brands: "JA!" (ALDI/REWE) = Eigenmarke

7. PRICE VERIFICATION:

   - Common mistakes: including subtotals as items, missing multi-line items, missing deposits
   - Trust the right-aligned price over calculated amounts

8. CARD NUMBER HANDLING:

   - They appear next to indication of the payment method, "Karte", "girocard Nr.", "PAN"

9. TRANSACTOION DETAILS AND MERCHANT HANDLING:
   - Detect the country and use respective language when processing the data
   - When country is unclrear assume it is Germany and the language is German
   - Date is likely to be formatted as YYYY-MM-DD or DD.MM.YYYY
   - Date/time information is often located next to the payment details
   - The receipt total amount is directly below the list of items, marked as "SUMME" or "ENDSUMME" or "ZU ZAHLEN". If that is not clear take it from the payment information.

Step 3: SYSTEMATIC QUANTITY LINE ASSIGNMENT WITH LAYOUT PATTERN DETECTION

CRITICAL PRINCIPLE: Receipt layouts are CONSISTENT within a single receipt.
Once you determine if quantity lines appear ABOVE or BELOW items, this pattern applies to the ENTIRE receipt.

ALGORITHM:

a) Identify all quantity lines:
   - Lines with "N x price" or "N Stk x" or "N.NNN kg x price €/kg"
   - Lines with NO right-aligned price
   - Typically indented
   - In table format: quantity appears in same row as item

b) DETECT THE LAYOUT PATTERN (do this FIRST):
   1. Find the first quantity line where you can clearly calculate the result
   2. Calculate: quantity × unit_price = calculated_total
   3. Check item ABOVE: does calculated_total match item_above.total_price? (±0.02)
   4. Check item BELOW: does calculated_total match item_below.total_price? (±0.02)
   5. For table format: quantity is on SAME LINE as item (pattern = "inline")
   6. Whichever matches → that's the pattern for the ENTIRE receipt
   7. Remember: "QUANTITY ABOVE ITEM" or "QUANTITY BELOW ITEM" or "INLINE"

c) APPLY THE PATTERN to all remaining quantity lines:
   - If pattern is "QUANTITY BELOW ITEM":
     * For each quantity line, assign to the item ABOVE it
     * Calculate to verify: quantity × unit_price should equal that item's price (±0.02)
   - If pattern is "QUANTITY ABOVE ITEM":
     * For each quantity line, assign to the item BELOW it
     * Calculate to verify: quantity × unit_price should equal that item's price (±0.02)
   - If pattern is "INLINE":
     * Quantity is already on the same line as the item
     * Extract directly from the row

d) HANDLE EXCEPTIONS:
   - If a specific quantity line doesn't match the pattern:
     * Try the opposite direction as fallback
     * If still no match: leave that item without quantity, add note if significant
   - Track how many followed pattern vs. exceptions

e) FINAL VERIFICATION:
   - After all assignments, verify each item with quantity
   - Confirm: quantity × unit_price = total_price (±0.02)
   - If verification fails, note the discrepancy

f) QUANTITY <> 1 RULE:
   - ONLY include quantity and unit_price fields when quantity is differet from 1
   - When quantity = 1: use ONLY total_price field, omit quantity and unit_price
   - Example: "1 x 4.99 €" → just {total_price: 4.99}
   - Example: "3 x 1.99 €" → {quantity: 3, unit_price: 1.99, total_price: 5.97}
   - Example: "0.8 kg x 3.99 €/kg" → {quantity: 0.8, unit_price: 3.99, total_price: 3.19}
